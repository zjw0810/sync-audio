# ADR 0004：密码哈希、会话与登录限流

- 状态：已采纳
- 日期：2026-10-24

## 背景

早期版本把房间密码和管理密码以明文存在 `settings.json`，登录没有失败限制，会话只存在内存里（重启即失效）。这些在局域网自用可以接受，但一旦暴露到公网就是明显问题。

## 决定

- **密码用 scrypt 哈希**（`crypto.scryptSync`，16 字节随机盐，64 字节输出），旧版明文在启动时自动迁移；
- **会话 Cookie**：`HttpOnly; SameSite=Lax; Max-Age=12h`，token 为 18 字节随机数；
- **会话持久化**到 `sessions.json`，重启后已登录设备不用重新输入；
- **登录限流**：同一 IP + 作用域 10 分钟内失败 5 次，封禁 5 分钟，返回 429 + `Retry-After`；
- **修改房间密码**会让所有 room 会话立即失效并踢掉对应 WebSocket（4001）。

## 后果

- 房间密码明文只在"首次生成 / 迁移 / 主动重置"的当前进程内可回显，重启后控制台显示「已设置，输入新密码以重置」；
- 管理密码忘记只能通过环境变量 `ADMIN_PASSWORD` 或删除 `settings.json` 重置；
- `sessions.json` 里是 bearer token，等同于密码，文件权限依赖系统用户目录；
- 没有 CSRF token：状态修改接口依赖 `SameSite=Lax` + 同源检查，公网部署建议再加反向代理鉴权。
