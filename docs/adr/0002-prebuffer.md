# ADR 0002：预缓冲 150ms（本机声音）/ 300ms（文件）

- 状态：已采纳
- 日期：2026-10-23

## 背景

`scheduledTime = Date.now() + 预缓冲`。预缓冲太短，客户端还没收到块就要播；太长，端到端延迟和主机监听的回声都会变大。

链路本身还有固定开销：

- WASAPI 环回采集 + 重采样：约 50–100ms；
- 客户端抖动缓冲 + 输出延迟补偿：约 80–120ms；
- 网络传输：局域网 1–5ms，公网 20–100ms。

## 决定

- **本机声音（实时源）：150ms**，可用 `SYNC_LIVE_PREBUFFER_MS` 调整；
- **文件播放：300ms**，文件不是实时源，多出的 150ms 用来吸收解码抖动和网络抖动。

## 后果

- 局域网端到端约 300ms，仍低于"看视频对不上口型"的明显阈值；
- 公网建议把 `SYNC_LIVE_PREBUFFER_MS` 调到 300–500，否则 RTT 抖动会频繁触发晚到块；
- 预缓冲只决定"计划播放时间"，不决定实际延迟；实际延迟还要加上客户端缓冲和输出延迟。
- 主机自己监听时，300ms 的延迟在房间里能听出回声，因此默认建议主机不加入房间，或用音量合成器把输出单独路由。
